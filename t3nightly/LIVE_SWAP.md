# Live swap recorder

`live-swap-record` records a live host without restarting it. Run it locally on that host with a matching, dependency-installed production RPC source tree:

```sh
python3 t3nightly/live-swap-record --host studio --rpc-tree /internal/rpc-tree --start now --duration-s 900 --turn
```

Use `--until 2026-11-01T18:15:00Z` for an absolute end. Timestamps require a timezone. The command submits a launchd job on macOS or a transient systemd-user service on Linux and returns its label and receipt directory. It never connects to another host over SSH. Engine sources are snapshotted into the run; the job records its own PID, PGID, process identity and hard deadline. The default path is `~/.agent-rails/lanes/t3-hot-swap-cutover/proof/live-swap-<host>-<UTC timestamp>/`. Studio run and RPC paths must be internal storage.

`--provider claude` is the only accepted provider and resolves to the built-in `claudeAgent` instance; the model is pinned to `claude-haiku-4-5`. `--turn` submits exactly one Claude Haiku turn through the running server's CLI in the already-registered `~/.t3/scratch` project. It does not register a project. The provider waits on a deadline-bound gate under the run directory. After NEW is observed and its replacement subscription attaches, the recorder releases the gate, allowing automatic continuation to complete with the original output nonce. Without a swap the gate releases during the last 45 seconds. It never sends a follow-up user prompt. Use `--thread ID` instead for observer mode: the same production client watches that thread read-only and no T3 turn or active run is held. A held turn keeps a provider run active through the freeze; both observed freeze-timeout rollbacks had one in flight, so the zero-disconnect proof uses observer mode. Observer mode grades every transport criterion below and skips only the provider-turn criteria; receipts record `mode`.

Authentication reuses the live install acceptance `restart_session`: the runtime's `auth session issue` CLI reaches the running server, writes the credential only into a private temporary 0600 bearer file, and revokes it at teardown. No direct write to live userdata is performed. Credentials and RPC errors are never logged. Only `orchestration:read` is requested by the observer credential: the owner CLI submits the one allowed scratch turn, so neither operate nor environment-maintain scope is needed by the observer. Signals are blocked from issuance through the protected yield, and revoke runs under a blocked mask even when setup is interrupted. Teardown first ignores/cancels SIGALRM, then attempts revoke before gate/client cleanup; each action is independently guarded. The CLI revoke acknowledgment and a fresh active-session listing must both confirm revocation; failed revoke or retained auth files fail the grade. The bounded credential expires if revoke cannot reach the host, but that is never reported as verified revoke.

The probe uses production EnvironmentSupervisor and ConnectionDriver with handoff client IDs, lifecycle hint, first reply and confirmation observations. It records all supervisor/presentation changes, physical WS connection and close events, fresh HTTP request outcomes/latency at 20 ms intervals (appended HTTP JSONL, a 128-sample receipt window and compact 250 ms status updates), keep-alive behavior, served versions and thread event cursors. Expected physical WS replacement during handoff is recorded separately from a disconnect presented to the user. Short read-only queries against only the selected thread compare persisted event IDs with received IDs; they do not hold a transaction across samples or infer gaps from globally noncontiguous sequence numbers.

Recording ends at the requested limit or after a version change and at least 65 seconds of NEW observations (60 seconds plus a 5 second margin), whichever comes first. A truncated NEW settling interval fails; its duration is measured from actual HTTP observations before teardown, not from cleanup time. A successful swap grade requires every presentation after initial connection to remain `connected` (including rejecting `connecting`), matched lifecycle handoff hint/reply/confirmation with a successful reply settlement and either a successful confirmation settlement or the old socket closing after the confirmation was sent and before the server's receipt timeout (the old server relinquishes as soon as the last confirmation arrives, so that close is the planned handoff and is not counted as a thread-stream failure), no failed HTTP or thread stream (HTTP probes wait up to the launcher's 30 s hold budget, so a held request shows in `flipGapMs` and `maxHttpGapMs`, not as a failure), no refused connection, no missed event or cursor reset, a final version different from the initial one (A→B→A fails), and, in turn mode, automatic completion of the original provider turn on NEW without a follow-up prompt. A healthy recording with no version change is `NO-SWAP-OBSERVED`, never PASS. JSON and Markdown receipts retain the bounded probe and turn evidence; probe.json.http.jsonl retains every HTTP response and failure. Confirmation evidence matches wire client ID and sequence, not the diagnostic session ID. Gate helper processes have their own deadline and captured identities; teardown releases the gate and signals only recorded matching PIDs.

No service restart, installer dispatch or live update RPC is part of this command. Linux uses `systemd-run --user` with `RuntimeMaxSec`; macOS uses its own launchd label and the worker's signal deadline. Normal recorder shutdown closes the client after taking the final continuity sample; that intentional close is not a presented disconnect.

The worker requests its own private-unit bootout at exit. An independently detached deadline watcher also unloads the exact recorded unit, verifies `launchctl print` failure or Linux `LoadState=not-found`, and finalizes the receipt. A provisional receipt is not successful until unit absence is verified. This watcher also reaps only identity-matched recorded PIDs after an expired worker deadline. No manually invoked post-run unload is needed. `finished.json` identifies `watcherFinalized:true` and the final auth/unit status.
